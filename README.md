# **twampy** – Инструмент для мониторинга сетевой производительности

**twampy** — это утилита для измерения и мониторинга параметров сети в реальном времени с использованием протокола **TWAMP (Two-Way Active Measurement Protocol)**. Она позволяет оценивать качество каналов связи, измеряя задержки (latency), джиттер (jitter) и потери пакетов (packet loss) между двумя узлами сети. Реализована интеграция с Zabbix.

## 🔍 **Для чего нужен twampy?**

- **Мониторинг сетевой производительности**: Измерение задержек, джиттера и потерь пакетов в двустороннем режиме (outbound, inbound, round-trip).
- **Диагностика проблем**: Выявление узких мест, нестабильности или ухудшения качества связи между узлами.
- **Интеграция с Zabbix**: Автоматическая отправка собранных метрик в систему мониторинга **Zabbix** для визуализации и анализа.
- **Гибкая настройка**: Поддержка работы как в роли **отправителя (sender)**, так и **отражателя (reflector)**, а также в режиме **контроллера (controller)** для управления сессиями TWAMP.

---

## 🚀 **Как работает?**

1. **Отправитель (Sender)**:
  - Отправляет тестовые пакеты на удалённый узел (отражатель).
  - Измеряет время доставки пакетов в обоих направлениях (outbound и inbound).
  - Рассчитывает задержки, джиттер и потери пакетов.
2. **Отражатель (Reflector)**:
  - Принимает тестовые пакеты от отправителя и возвращает их обратно.
  - Не требует сложной настройки — достаточно запустить в режиме прослушивания.
3. **Контроллер (Controller)**:
  - Управляет сессиями TWAMP между отправителем и отражателем.
  - Подходит для автоматизации тестирования в больших сетях.
4. **Интеграция с Zabbix**:
  - Автоматически создаёт хосты, шаблоны и элементы данных в Zabbix.
  - Отправляет метрики (min/max/avg задержки, джиттер, потери) для визуализации на дашбордах.

---

## 📌 **Ключевые возможности**
  
✅ **Гибкие настройки сессий** – Настройка интервала отправки пакетов, количества пакетов, TTL, DSCP и других параметров.  
✅ **Автоматическое обнаружение сессий** – Отслеживает уникальные сессии и обновляет их в Zabbix.  
✅ **Логгирование** – Поддержка разных уровней детализации логов (quiet, verbose, debug).  
✅ **Low-Level Discovery (LLD)** – Автоматическое обнаружение и добавление новых сессий в Zabbix.

## 🛠 **Примеры использования**

### 1. Запуск отправителя (Sender)

```bash
python3 twampy.py sender --near_end :20000 --far_end 192.168.1.100:20001 --count 100 --interval 100
```

- Отправляет 100 пакетов с интервалом 100 мс на узел `192.168.1.100:20001`.
- Результаты автоматически отправляются в Zabbix.

### 2. Запуск отражателя (Reflector)

```bash
python3 twampy.py responder --near_end :20001
```

- Прослушивает порт `20001` и отражает пакеты обратно отправителю.

### 3. Просмотр таблицы DSCP

```bash
python3 twampy.py dscptable
```

- Выводит таблицу соответствия имен DSCP и их значений (для настройки QoS).

## 📊 **Используемые метрики**


| Метрика         | Описание                                            |
| --------------- | --------------------------------------------------- |
| **Outbound**    | Задержка в направлении от отправителя к отражателю. |
| **Inbound**     | Задержка в направлении от отражателя к отправителю. |
| **Roundtrip**   | Общая задержка "туда и обратно".                    |
| **Jitter**      | Вариация задержки между пакетами.                   |
| **Packet Loss** | Процент потерянных пакетов.                         |

## 🔗 **Требования**

- Python 3.x
- Библиотека `zabbix_utils` (для интеграции с Zabbix).
- Доступ к Zabbix API (если используется интеграция).
- Права на создание хостов и шаблонов в Zabbix (при первом запуске).

---

## 📝 **Примечания**

- Для безопасности рекомендуется использовать **токен доступа** вместо логина/пароля Zabbix.
- По умолчанию используется порт `20000` для отправителя и `20001` для отражателя.
- Поддерживаются пользовательские имена хостов и сессий для удобства идентификации в Zabbix.
